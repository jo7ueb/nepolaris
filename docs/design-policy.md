# 設計方針（draft）

更新日：2026-11-24 / 状態：実装前の要求ベースライン

> **本書は方針を記録するもので、詳細DB設計の確定ではない。**

## 1. 目的と境界

**目的：** 複式簿記を基礎に、個人の財務状態を「正しく記録し、観測し、判断する」Webアプリを作る。

- 財務会計：仕訳、元帳、試算表、B/S、期間収支、残高照合、月次締め
- 管理会計：純資産推移、増減要因、生活費分析、資産配分、流動性、将来の予実分析
- 運用：個人・シングルユーザー、月に数回CSV取込、月末に評価額を入力する
- **対象外：** 金融機関API/スクレイピング、リアルタイム同期、FX・株式の全約定管理、厳密な税務申告計算、自動売買、多人利用

最優先は、データの会計整合性・説明可能性・可搬性である。

## 2. 会計の不変条件

1. すべての確定仕訳は複数の明細（Posting）をもち、**借方合計＝貸方合計**。
2. 勘定科目は資産・負債・純資産・収益・費用のいずれかに属する。
3. 帳簿残高は確定済み仕訳の積み上げから算出する。スナップショットを直接残高の上書きに使用しない。
4. 取引元データ、月末評価入力値と、生成された仕訳は分離する。
5. 訂正は監査可能にする。原本を破棄せず、訂正・取消と生成根拠をたどれる。
6. 入出金・資産間振替と、収益・費用・評価変動を混同しない。
7. 記帳漏れを説明不能な損益として埋め合わせない。
8. 同一操作の再実行で同じ仕訳を増殖させない（冪等性）。
9. 初期帳簿通貨はJPY。金額は整数円またはDecimalで扱い、二進浮動小数点を会計計算に使わない。
10. 帳簿処理と分析ビューは分離し、分類やダッシュボードの変更で確定仕訳を破壊しない。

## 3. 管理対象

| 対象 | 主に記録する取引 | 決算時の管理 |
| --- | --- | --- |
| 普通預金 | 給与・生活費・引落・振替をCSV取込 | 実残高と照合 |
| 定期預金 | 預入・解約・受取利息 | 口座残高と照合 |
| FX | 他口座との入出金（資産移動） | **口座純資産**を入力し期間損益を調整 |
| 証券 | 他口座との入出金（資産移動）、必要に応じて明示的な入金等 | **口座総評価額**（口座内現金を含むか明記）で評価調整 |
| iDeCo | 掛金拠出（原則、資産振替） | 引出制約を設定し月末評価額で調整 |
| 借入・負債 | 元本返済・利息支払 | 債務残高の照合 |

- 通常の家計支出は費用と資産減少の仕訳。
- 自己資金の口座間振替、証券への入金、iDeCo掛金の拠出は原則、**支出ではなく資産間移動**。別途発生する手数料等は費用とする。
- 初期残高の相手は開始純資産科目等に計上し、期間損益と混同しない。
- 資産クラス・運用目的・流動性・引出制約・リスク区分は、勘定科目の借貸属性とは別に持てるようにする。
- 証券口座の「現金を含む総評価額」を1科目で管理する場合、口座内現金を別科目で二重計上しない。

## 4. 月末評価と調整仕訳

売買履歴をすべて保持しなくても、期間の**口座純資産／評価額**と、帳簿に反映済みの資金移動から運用による差額を計算できる。

例：

- 前月末FX口座純資産：500,000円
- 今月の銀行からの入金：100,000円
- 今月末のFX口座純資産：630,000円

まず入金時の仕訳：

| 借方 | 貸方 | 金額 |
| --- | --- | ---: |
| FX口座 | 普通預金 | 100,000 |

すると調整前帳簿残高は600,000円、観測した月末純資産は630,000円。差額30,000円を次のように計上する。

| 借方 | 貸方 | 金額 |
| --- | --- | ---: |
| FX口座 | FX期間運用損益 | 30,000 |

負の差額では損失の仕訳を起こす。

**重要：** この差額は期間の総合的な運用損益（確定損益・評価変動等を含み得る）であり、取引明細を記録しない限り「実現損益」や「税務上の利益」と同一視できない。配当・利息・手数料等を個別記帳済みなら、調整前残高に反映された状態から**残差のみ**を計上する。

運用口座の基準は口座ごとに固定する：評価額に口座内現金を含めるか、何の残高を観測したのか、基準日、通貨、情報源等。

### 評価処理の要件

- 入力された月末評価額は原本（ValuationSnapshot）として保存する。
- 調整前帳簿残高・差額・予定仕訳をプレビューする。
- 同一口座・同一基準日の評価を再実行しても多重計上しない。
- 後日訂正する場合は旧調整の取消／差額訂正を行い、履歴と参照関係を残す。
- 未照合取引や不明な入出金がある場合、評価差額を無条件に運用損益としない。
- 基準時点を跨いだ遡及仕訳は決算への影響を検出する。

## 5. CSV取込

### 標準的な取込フロー

1. 金融機関からダウンロードしたCSVファイルを選択する。
2. 金融機関・フォーマットごとの列対応を設定／再利用する（日付・金額・入出金・摘要・残高・IDなど）。
3. 元ファイルと元行（ImportBatch/ImportRow）を保存し、文字コード・日付・金額等を検証する。
4. 既存取引との重複候補、口座間振替候補、カテゴリ候補を検出する。
5. **プレビューと承認**を経て、仕訳を生成する。
6. インポート済みの行と生成仕訳の参照関係を保存し、残高照合に利用する。

### 守るべきこと

- 同じCSVの再取込で仕訳が重複しない。
- 取引IDがないCSVでは、日付・金額・摘要・残高などを使って候補を判定するが、**同日同額の別取引を無条件で同一視しない**。
- 入出金両側のCSVに載った振替を二重計上しない。
- 未分類取引や曖昧な振替は未確定として明示し、誤った仕訳を自動確定しない。
- 自動分類のルールは編集・再利用できるようにする。
- CSVファイル形式は可変。初期版は汎用マッピングから開始し、特定金融機関対応は後から追加可能とする。
- 当面のZaim利用は独立した並行運用。nepolarisの正本データ取得をZaimに依存させない。

## 6. データモデル（概念）

- `Book`：会計帳簿、基準通貨、期首
- `Account`：勘定科目、種類、親子関係、資産属性
- `FinancialAccount`：実際の金融口座と帳簿科目とのマッピング
- `JournalEntry`：仕訳ヘッダ、日付、摘要、状態、原本参照、訂正参照
- `Posting`：借方／貸方・金額・科目
- `ImportBatch` / `ImportRow`：CSV原本と明細、重複判定や分類状態
- `MappingRule`：CSV列マッピング、分類ルール
- `ValuationSnapshot`：口座、評価基準日、評価額、評価範囲、入力根拠、調整仕訳参照
- `Reconciliation`：時点・口座・実残高・帳簿残高・差額・確定状態
- `AccountingPeriod`：対象期間、締め状態、再オープン履歴
- `Budget`：将来の予実管理（初期MVPには必須でない）

各エンティティの確定スキーマ・一意制約・更新制御は専用Issueで決定する。ORM/DB/フレームワークは未決定。

## 7. 月次決算ワークフロー

1. 対象月のCSVを取り込む。
2. 未分類、未処理、重複、口座間振替の照合候補を解消する。
3. 普通預金・定期預金・負債等の実残高と帳簿残高を照合する。
4. FX・証券・iDeCo等の評価額を入力し、調整差額をプレビューする。
5. 評価調整仕訳を確定し、試算表・B/S・期間収支を確認する。
6. 月次を締め、以後は明示的な再オープン・訂正処理以外で変更できないようにする。

入出金の未記帳が評価差額に紛れ込まないよう、決算前に照合の状態を検証する。

## 8. 財務諸表と管理会計

### 財務会計の表示

- 仕訳帳、総勘定元帳、残高試算表
- B/S：資産・負債・純資産と時点比較
- P/L相当：給与等・生活費・運用の期間損益を区分
- 口座残高と照合状態、評価調整の根拠

### 管理会計の表示

- 純資産の月次推移と増減要因（生活収支／運用損益／その他）
- 金融資産の構成比、現預金と投資資産の割合
- 流動性・引出制約別の残高
- 支出カテゴリ別分析

### 次段階

予算・実績差異、生活防衛資金、固定費率、貯蓄率、将来資金繰り、配分目標・リスク集中のモニタリングなど。

**注意：** FX口座の純資産額だけでは建玉想定元本やレバレッジのリスク量は算出できない。必要ならリスク指標専用入力を追加する。正確なキャッシュフロー計算書は将来の機能とし、初期版は入出金の分類・推移を中心とする。

## 9. デプロイと情報保全

- Docker Composeで動作する個人用Webアプリ。技術スタックは候補（例：FastAPI/React/SQLite）であり未決定。
- 公開リポジトリと実データを分離し、**本番の口座情報・取引CSV・バックアップ・認証情報はGitに追加しない**。
- 初期設定はローカルバインド等、安全側の公開範囲を採用する。外部アクセスはVPN/適切な認証等を前提とする。
- DB、元CSV、評価スナップショット、設定を含めて整合性あるバックアップ／復元を可能にする。
- CSV等の完全エクスポート手段を用意し、別製品・別実装へ移行できるようにする。

2. 手動仕訳・取引一覧・元帳・試算表
3. CSV取込・重複検出・振替照合・承認
4. 口座残高照合
5. 月末評価入力・評価調整仕訳

## 11. 最低限の受け入れテスト

- 不均衡仕訳を拒否し、借貸一致を保証できる。
- 同一CSVの再取込、同じ口座間振替の両側取込で、仕訳が増殖しない。
- 例：前月末FX純資産50万円、月中純入金10万円、月末純資産63万円 → 調整3万円を**一度だけ**計上する。
- 評価額訂正時も帳簿は一致し、監査証跡・元値が残る。
- 不明な資金移動を自動的に損益と解釈しない。
- 月次締め後の変更は明示的な操作を要する。
- 帳簿残高と実残高の不一致を検出できる。
- バックアップから原本と仕訳・設定・評価履歴を再現できる。
