# 開発の動機と検討経緯

更新日：2026-11-24

## 1. 出発点：支出管理と浪費抑制

安定した給与収入を機に、どんぶり勘定だった家計を見直そうと考えた。日常決済の多くはデビットカード等の履歴が残る手段なので、支出の自動取得・分類と月次の予算実績管理が当初のテーマだった。

最初は家計簿アプリ（Zaim、マネーフォワード ME）を比較し、支出の現状把握にはZaimを試す方針とした。**予算額は支出実績を観測してから決める**。

## 2. 本当の目的は支出管理より広い

家計の支出・浪費の抑制は目的の一部でしかない。預貯金（普通・定期）、証券、FX、iDeCo、必要に応じて負債を横断して、次の問いに答えたい。

- 現在の資産・負債・純資産はいくらか。
- 純資産は月ごとにどれだけ増減したか。その原因は生活収支か運用損益か。
- すぐ使える資金と引出し制約のある資金はどの程度か。
- 金融資産の配分・リスク集中度はどうなっているか。
- 予算と実績をどう比較して将来の資金配分を考えるか。

目指すのは単なる家計簿でなく、**個人の財務諸表と管理会計・分析の基盤**である。

## 3. 既存ソフトを検討した結果

- **Zaim：** 生活費の把握には便利。まず並行利用できるが、独自アプリの正本や必須依存先とはしない。
- **マネーフォワード ME：** 資産集約機能は選択肢だが、マネーフォワード クラウド会計の使用経験に基づく使い勝手への不満があるため、積極採用しない。
- **GnuCash：** 使用経験あり。複式簿記の実装としては実績がある一方、ローカルデスクトップアプリの操作性やダッシュボード・管理会計体験が今回の目標と一致しない。
- **専用の投資・家計管理ツール：** いずれも用途の一部分には強いものの、複式簿記に根差した一貫した観測・分析体験を求めている。

**結論：** 個人用のミニマルなWebアプリを作る価値がある。

## 4. 開発を現実的にする割り切り

- **金融機関API連携はしない。** 月に数回、CSVを手動インポートすれば十分。
- **投資の全売買履歴は要求しない。** FX・証券・iDeCoの月末評価額／口座純資産を手で入力する。
- **内部会計は複式簿記を省略しない。** 入力負担の低減はUIと集計・仕訳生成で実現する。
- **観測データは正確に保持する。** 売買内訳がない場合の期間運用損益は推計であり、実現損益・未実現損益・税務所得には分解しない。
- **コンテナによるセルフホスト。** API運用、SaaS契約、複雑なインフラを前提にしない。

## 5. コードネーム

nepolaris = NEPO + Polaris（北極星）。

複式簿記という確かな土台に立ち、財務の状態を観測して今後の判断の方向性を得る、という意味を込めた。

プロダクトの説明用サブタイトルは **Personal Financial Observatory**。

## 6. 成功の定義

毎月のCSV取込と月末評価額入力を続けるだけで、帳簿が整合し、純資産の変化とその要因を見渡せること。その観測をもとに支出・資産配分・将来の資金計画を判断できること。

**優先順位：会計の正確性 ＞ データの追跡可能性 ＞ 日常の操作負担の少なさ ＞ ダッシュボードの装飾性。**
